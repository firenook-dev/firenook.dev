Kept data's Firestore file grows with use and never shrinks by itself:
deleted and rewritten documents leave free pages behind. `state:inspect`
shows what the file holds and how much of it is free, and `state:compact`
gives the free pages back to the disk. Both work on stopped data only.

## How big is the store

While the emulators run, the console's Overview shows the Firestore file's
size on disk on the Firestore card, beside the number of documents. The file
is `firestore/firenook.redb` in the state folder, `.firenook/state` with
`--keep-data`.

## Inspect

Stop Firenook, then run `state:inspect` with the state folder you start
with:

```console
$ npx firenook state:inspect --state-dir .firenook/state
Reading every page of the Firestore file once (minutes for tens of gigabytes)…
~/demo-shop/.firenook/state/firestore/firenook.redb: 18 MB

  Documents                       1,000   579 KB of keys and values in 1 MB of pages
  Field index                     6,000   231 KB of keys and values in 565 KB of pages
  Field index names                   7   296 B of keys and values in 4 KB of pages
  Collection index                1,000   82 KB of keys and values in 193 KB of pages
  Collection-group index          1,000   91 KB of keys and values in 217 KB of pages
  Store metadata                      5   122 B of keys and values in 4 KB of pages
  Old documents table                 0   0 B of keys and values in 0 B of pages
  Free pages, redb's own                  16 MB

firenook state:compact --state-dir ~/demo-shop/.firenook/state returns the free pages to the disk.
```

Each row is a table in the file, with its number of entries and its size:

| Table | What it holds |
| --- | --- |
| Documents | Every document |
| Field index | Each document's top-level fields, sorted by value. It serves `==` and `in` filters, and `orderBy`, range filters and cursors on one field |
| Collection index, Collection-group index | Which documents each collection and collection group holds |
| Store metadata | The saved count of documents, and similar records |
| Old documents table | Documents in the layout of releases before 0.1.0-next.3, emptied once they are copied |
| Free pages | Space that deleted and rewritten documents left behind |

This store held 4,000 orders with six fields each, of which 3,000 were
deleted: 16 MB of its 18 MB is free.

## Compact

`state:compact` rewrites the file without its free pages. Every document
stays as it is:

```console
$ npx firenook state:compact --state-dir .firenook/state
Compacting the Firestore file, after copying it (minutes for tens of gigabytes)…
~/demo-shop/.firenook/state/firestore/firenook.redb: 18 MB → 2 MB (16 MB back to the disk) in 0 s. Every document is as it was.
```

Before it starts, it copies the file beside itself, as a copy-on-write clone
where the file system has one, and removes the copy once the compaction
succeeds. If the compaction fails, the copy stays and the message names it;
the store itself is repaired at the next start.

The copy needs disk space when the file system cannot clone. If there is
not enough, nothing is changed, and the message asks you to free some disk
or to pass `--no-copy`, which compacts without a copy:

```sh
npx firenook state:compact --state-dir .firenook/state --no-copy
```

<Aside type="caution">
With `--no-copy`, a compaction that is interrupted leaves a store the next
start repairs by reading the whole file. Take an
[export](/docs/data/export) first if the data matters.
</Aside>

## Stopped data only

Both commands lock the state folder, as the emulators do. While Firenook
runs on it, they refuse and change nothing:

```console
$ npx firenook state:inspect --state-dir .firenook/state
Reading every page of the Firestore file once (minutes for tens of gigabytes)…
~/demo-shop/.firenook/state is in use: stop the emulator first
```

Both need `--state-dir`, even for data kept with `--keep-data`:

```text
Firenook: state:inspect needs --state-dir (the saved data), as given to emulators:start; stop the emulator first
```

On a large store each takes minutes: inspect reads every page once, and
compact rewrites the file.
